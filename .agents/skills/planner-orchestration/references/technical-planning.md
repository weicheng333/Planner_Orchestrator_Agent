# 技术方案门

用于新规划及涉及技术变更的 replan。产品需求确认不是技术选型确认，也不是实施授权。

## 主动识别

从 TaskSpec 的目标、范围、约束及未知项提取已定与未定技术决定。按相关性检查：

- 客户端框架与平台能力：跨平台、原生依赖、团队现有代码及经验。
- 数据存储与协作：数据模型、一致性、并发、防重、隔离及恢复。
- AI 服务与数据来源：能力、质量、隐私、调用费用、来源及服务约束。
- 部署与运维：已有基础设施、托管或自管、监控、维护及费用。
- 其他相关事项，如认证、图片存储、第三方依赖与许可证。

列表不是固定问卷；纯文档或已定实现的小修可以说明无选型。不得把未知预算、厂商或框架补成用户要求。

## 比较、取证与决策

每个相关未定选型提供二至三个可行方案，说明适配原因、优势、代价、成本依据、风险和推荐理由。仅一个可行方案时列出排除其他方案的约束，不制造虚假选项。已有确认选型不重复询问，除非证据揭示冲突。

厂商现状、价格、版本、许可证、实测性能等需要可信外部证据时，创建 research 子任务，明确待核查问题、比较维度、来源要求、授权及完成条件。Planner 只综合证据，不替 Research 搜索；能力或权限缺失时输出 typed handoff 或审批请求，不自行调用或伪造证据。不确定成本标为未知，不能把相对 cost units 当实际费用。

技术方案比较是可回看的分析内容；询问用户时遵守宿主规则及用户展示偏好，不用产物形式绕过文字多选限制。

## 确认与实施门

ExecutionPlan.technical_review 标记每个决定为 RESEARCH_REQUIRED、AWAITING_CONFIRMATION 或 CONFIRMED。CONFIRMED 只来自真实用户选择或明确既有授权，保留选择及确认引用；推荐本身不是确认。研究完成但用户未选择时保持待确认。用户可以选择非推荐方案。

预算、第三方数据发送、付费、部署及重大选型必须明确获得相应批准。默认先展示技术方案，由用户确认后细化完整实施计划；已明确授权代理决定的低风险细节可在授权范围内处理，仍保留依据。

未定阶段可以生成研究/比较计划；含实施节点的完整计划保持 DRAFT 或 APPROVAL_REQUIRED，不下发依赖未确认技术决定的实施任务。实施节点列 technical_decision_ids，确认后生成新计划版本再校验。确认引用的存在仅是合同检查，不是 MCP 对用户身份或审批有效性的独立证明；下发前核对真实记录和权限。

选型改变产品范围、关键验收或违反用户约束时，交回 intake_spec 修订 TaskSpec；没有改变产品需求时只更新技术方案和执行计划，不要求用户重新确认全部产品清单。replan 保留已确认且未受影响的决定与成功回执，变更项重新取证和确认。

新计划必须显式包含技术审查；旧计划 null 只用于兼容读取，不可解释为技术就绪。MCP 不从自然语言猜测漏掉的维度，语义覆盖由 Planner 检查并在验收中核验。
